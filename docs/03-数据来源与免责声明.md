# 数据来源与免责声明

## 一、数据来源

### 1. 业务数据

**全部为合成示例数据（Synthetic Data）**，不来自任何真实客户、真实保单或真实业务系统。

| 类别 | 说明 |
| --- | --- |
| 产品代码 | 如 `DEMO-P2-001`，显式带 `DEMO` 前缀以避免与真实产品混淆 |
| 产品分类 | P1–P5，参考公开监管文件中的产品分类口径 |
| 风险等级 | 产品 R1–R5、客户承受能力 C1–C5 |
| 保费与收入 | 演示用数值，用于验证阈值型规则是否命中 |
| 场景事实 | 9 个场景为构造的风险样本，用于验证规则分支 |

数据集中在 `js/rules-engine.js` 中定义，可从 `assets/demo-data/scenario-baseline.json`
查看每个场景的完整输入快照与预期判定结果。

### 2. 规则依据

规则的判定依据来自**公开发布的规定文件**，出处随每条规则一并维护：

- 规则引擎内：`legal_basis` 字段
- 结构化清单：`assets/demo-data/rule-catalog.json`
- 可读文档：[`docs/01-规则清单.md`](./01-规则清单.md)
- 引擎内 `pack()` 导出的证据包也携带参考链接字段

对于监管要求中**可由机构自行确定**的部分（如产品上架渠道、事件触发机制），
本项目显式标注为 **「机构策略示例」**，不冒充为监管强制要求。

## 二、免责声明

### 1. 项目性质

本项目是**学生竞赛场景下的教学演示原型**，目的是验证"agent 化/规则化的适当性控制闭环"
在工程上是否成立。它**不是**：

- ❌ 真实银行或保险机构的上线系统
- ❌ 合规认证工具或合规意见
- ❌ 法律意义上的投保、承保或核保结论

### 2. 系统边界

| 项目 | 说明 |
| --- | --- |
| 数据源 | 未接入任何生产系统、核心系统或真实数据库 |
| 运行方式 | 100% 浏览器内存运行，无后端、无网络请求 |
| 签名勾选框 | 仅模拟"已核验事实"，**不构成**电子签名或身份认证 |
| 导出记录 | 浏览器内存会话，刷新即清空，**不具备**持久化、数字签名或防篡改能力 |
| 规则覆盖 | 15 条示例规则，**非完整适当性合规认证**，未命中不代表合规 |
| 故障测试 | 仅验证预设降级分支，**不代表**生产环境容灾能力 |
| 保存期限 | 界面提及的生产保存目标为设计描述，**本机演示不实现**该保存承诺 |

### 3. 商标与关联关系

项目所用名称、标识、界面文字与流程设计，**仅为说明银行业务场景用途**。
若与任何企业名称、机构名称、产品名称相同或近似，均**不代表**该企业或机构的
正式产品、认可、背书、审批或合作关系。

### 4. 重要原则声明

- **禁止性事实不得通过任何书面声明予以覆盖。**
  演示中若存在"主动推介不匹配产品"的事实，即使其他声明要素齐备，仍判定为阻断。
- **服务不可用一律降级处理，不作静默放行。**
  "未查出问题"不等于"没有问题"。
- **规则不替代人工判断**，而是明确"人工该复核什么、该留存什么"。
